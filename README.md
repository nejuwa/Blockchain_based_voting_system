# Blockchain-Based Voting System – Software Requirements Specification (SRS)

## Project Overview

This repository contains the **Software Requirements Specification (SRS)** for a **Blockchain-Based Voting System** designed to improve the security, transparency, and trustworthiness of elections in Ethiopia. The SRS document clearly defines the system’s functional and non-functional requirements, constraints, actors, and use cases, serving as a foundation for design and implementation.

## Objectives

* Design a secure and tamper-proof voting system
* Enhance transparency and voter trust
* Prevent voter fraud and double voting
* Enable real-time and accurate result reporting
* Provide a scalable solution suitable for national elections

## Problem Statement

Traditional voting systems in Ethiopia rely heavily on manual processes, which are prone to inefficiencies, delays, and potential fraud. There is a critical need for a modern, digital, and trustworthy voting system that ensures election integrity and public confidence.

## Proposed Solution

The proposed system uses **blockchain technology** to store and verify votes in a decentralized and immutable ledger. Each vote is securely recorded, verified, and transparently counted without exposing voter identity.

## Software Development Approach

* **Model:** Agile Development Model
* **Rationale:** Agile enables incremental requirement refinement, stakeholder feedback, and adaptability to evolving electoral laws and policies.

### Agile Phases

* Requirements Analysis
* Iterative Refinement
* Validation and Review
* Approval for Implementation

## System Scope

### Included

* Voter registration and authentication
* Secure vote casting
* Blockchain-based vote recording
* Result computation and visualization

### Excluded

* Political campaigning features
* Hardware-based biometric authentication

## System Requirements

### Functional Requirements

* User registration and authentication
* Secure vote submission
* Blockchain ledger integration
* Admin and election commission dashboards
* Result generation and reporting

### Non-Functional Requirements

* High performance and fast validation
* Strong security and encryption
* Scalability for millions of voters
* User-friendly and multilingual interface

## Key Actors

* Voter
* System Administrator
* Electoral Commission
